## Report D — Target responsibility boundaries

`Authenticated session → trusted student context → conversation store (all raw turns, ordered) → context budget → model decision/tool declarations → backend authorization and typed parameter validation → DB snapshot + versioned policy/curriculum / approved RAG corpus → typed tool result with provenance → model explanation → typed claim/citation/action validator → REST or SSE response → UI`.

The model interprets language and proposes a tool call. The backend owns student binding, tool readiness, execution, and official status. The academic engine owns deterministic calculations against an approved policy version. The RAG catalog records who approved each source and which version was ingested; a repository label alone confers no authority. REST and SSE call one orchestration service and emit the same verified result. UI treats unavailable data as unavailable and never starts from a student-specific demo record in live mode.

## Report E — Remediation roadmap

1. **P0, data loss — implemented:** Fail on malformed history JSON and serialization; propagate history-read failures as unavailable in REST/SSE. Add positive and negative regression tests. Roll back by reverting local code; no migration.
2. **P0, institutional claims:** Write an ADR for policy/curriculum provenance and migration. Until an approved source exists, official eligibility must be unavailable. Requires compatibility review because current academic endpoints depend on demo policy and seed.
3. **P0, fake live data:** Remove planner fixture from authenticated initial/error state. Preserve explicit demo mode. Test first load, network failure, empty list, and account switch.
4. **P0, trust boundary:** Replace ad hoc XML/regex defenses with uniform structured serialization and verified claim contracts. This changes model prompts and responses; approve design and golden/evaluation plan before implementation.
5. **P1, RAG runtime:** Real embedding provider, persistent pgvector, source provenance, and controlled corpus migration. Compare retrieval on a fixed labeled set before changing threshold/topK. Paid live calls require separate authorization.
6. **P1, orchestration:** Merge REST/SSE tool execution into one path; Gemini interprets intent, backend validates and executes. Evaluate unseen paraphrases, mixed intents, failures and unauthorized requests.
7. **P1, full history:** Remove compaction only with storage cap and legacy-summary migration strategy. Recheck token counting against provider payload.
8. **P1, durable goals:** Replace live `InMemoryStudentFactStore` with authenticated persistent storage or remove cross-session behavior claim.
9. **P2, policy drift:** Consolidate course-code validation and numerical bounds under versioned contracts; remove frontend credit literals. Keep ordinary syntax regex and deterministic algorithms.
